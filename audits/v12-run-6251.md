## The three that mattered most

**`9c3f299`** closed three highs with one idea. The `m_of_n` quorum compared
the fields that read as coming from the chain and left out the two that read
as locally derived — the block gas limit copied from the simulated header,
and this module's own reading of the delegation code an endpoint returned.
Neither is local in the sense that matters. The block gas limit is the
ceiling `signing_gas_limit` computes against, so it reaches the chain rather
than the screen; the delegation reading decides whether a Calibur batch is
prepared as a batch or as a plain call to the wallet itself, which mines
successfully and executes none of it. The test is not who computes a field
but whether a dishonest endpoint can move it while leaving everything else
compared alone.

The third was the loop's exit. Only a successful simulation votes, so two
reverts left the agreement set empty and the loop fell out of the bottom
returning the last endpoint's failure — indistinguishable from the network's
answer. Under `m_of_n` one endpoint's word is exactly what the owner
configured the strategy not to act on, and a failure is the word most worth
doubting: its effects are unavailable by construction, and a human override
may sign it anyway.

**`186992`** is the one to read for how a fix travels. `token_label` already
treated a stored symbol as what it is — text seeded in thousands of rows from
an aggregated feed the owner was never asked about — and so kept only the
characters real symbols use and printed the resolved address beside the
symbol. The clear-signing bridge handed the raw string to the descriptor
engine instead. A row reading `USDC (0x<the real USDC>)` rendered a swap into
an attacker's token as an amount of the genuine one, with the address that
would have given it away left in the calldata the descriptor exists to spare
the reviewer. Two renderers of the same value, one rule between them.

**`186988`** was the last one open and is the smallest. `read_local_file`
stat'd a path, checked it named a regular file, and then opened the same path
again — two resolutions of one string, for a body the caller wrote in a
directory the caller owns. A regular file for the stat and a FIFO for the
open leaves the open holding a runtime thread, and neither the digest nor the
byte count can help, because both are computed on bytes the read has to
produce first. Nothing is asked of the name before the open now.

## Two decisions worth restating

**Positive evidence, not absent denial.** `187010` and `187011` are the same
mistake in the probe pipeline pointed in opposite directions: one inferred a
capability from the absence of a refusal, the other admitted a URL because
nothing in it looked like a credential. Both now name what they are looking
for. The probe records `eth_sendRawTransaction` only where the node answered
with a JSON-RPC error object, which is the node saying it read the request
and reached the method; the collector refuses userinfo outright, which is the
one credential form that needs no disguise to pass a filter reading paths and
query names.

**A credential in an endpoint is disclosed, not stored.** The runtime half of
`187011` is a different argument from the vendoring half. There the secret is
the owner's own, but this wallet quotes its endpoints back verbatim —
`wallet_list` to the agent, `network show` on screen, the disclosure text — so
a field repeated on every read cannot hold one. It is refused once where it is
entered rather than redacted at each site it would surface. This says nothing
about a key in a path or a query: that is indistinguishable from a path, and
an owner who types one has decided to use it. Only the collector, choosing
defaults on everyone's behalf, is strict about those.

A configuration already holding a userinfo URL now fails to load rather than
loading and leaking. That cost is real and deliberate; the error names the
repair.

## Convention

Run 6207's convention was that a fix commit names its findings as
`V12: <url> (finding <uid>, <severity>)`, so `git log --grep='<uid>'` finds
it. Most of this run's commits name their findings in prose instead — and
`9c8a2e9` and `9c3f299` say "two of run 6251's high findings" and "three"
without listing a uid at all — so the grep does not find them. The tables
above are the index for those. Only the three commits closing the lows
(`cb11a0e`, `72943ef`, `090d838`) carry the trailer.
