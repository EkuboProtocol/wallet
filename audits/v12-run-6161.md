## Findings whose severity changed

**179056 — low → high.** Correct as filed against `a58dfc2`, where the
sanctioned path also trusted contract-supplied metadata, so a legacy file was
no worse than `symbol()`. The post-audit commits inverted that: `tokens` became
the sole authority on what a reviewer reads, behind an owner-only quarantine.
That made `import_legacy_database` the only unauthenticated writer to the
trusted table, and the threat model puts the filesystem outside the boundary.

**179031 — medium → low.** Both encodings expand rather than contract, so the
decode allocates less than the URL string already resident. The ordering is
still worth fixing; the memory amplification described is not there.

**179045 — medium → info.** Documents a resolved state, not a live defect.

## Notable corrections to the report

**179057 is invalid.** The premise that `OFFSET n` costs O(n) does not hold:
both `list` statements order by `chain_id, address`, which is the table's
primary key, so SQLite walks that index and an offset past the end costs one
scan — less than the `SELECT COUNT(*)` the same handler already issues.

**179050 is understated** and still open. `wallet_add_network` returns the
probe target's response body verbatim to the caller, so it is an SSRF *read*
primitive rather than a blind probe. Separately, `docs/threat-model.md:171-174`
claims OS owner authentication runs before the first request to a proposed
URL. It does not, and the claim contradicts the same document's invariant 6,
which states network changes are deliberately *not* OS-authenticated. The doc
needs correcting with the fix.
